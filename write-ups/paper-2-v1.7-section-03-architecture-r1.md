## 3. Architecture

### 3.1 The three layers, revisited

Memory in sequence models is conventionally typed into three layers: the **parametric** (model weights — what the model knows), the **activational** (inference-time state — what the model is currently holding), and the **archival** (external store — what the system keeps beyond the window). The v1.6-line design placed collaboration memory entirely in the third layer, as prose, and treated the other two as out of reach: the activational layer was ephemeral by platform design — the working state dies with the window — and the parametric layer was frozen between training events, with no write path available to the collaboration at runtime. Everything the collaboration needed to survive had to fit the one layer that persists across windows, and that layer was text-first. The two ARGON costs follow directly from that forcing: what survived to the archive was a curated sample taken after the fact (AR-2), and every movement through the medium lost content at each boundary without accounting (AR-3). v1.7 does not add a fourth layer. It re-types the three. The parametric layer remains frozen at inference — that is a vendor property, named as such, not a design choice of this architecture; the bounded write path into this layer is training-side only (§4). The activational layer is promoted from an ephemeral byproduct to the substrate candidate — the working tensor. The archival layer is re-typed from text-first to tensor-first. The remainder of this section performs the re-typing layer by layer, and at each decision point names the documented failure that made the move non-optional rather than preferred.

### 3.2 The restorable unit: state + seed + manifest

The archival atom is not a document; it is a **state checkpoint**: a typed tensor object captured at a named capture point, with a manifest row. Manifests run over states, not strings: each row carries the object identifier, the capture point, the layer (which tier of the stack the object captures), the content hash (SHA-256 over the canonical byte encoding), the provenance (authoring instance and session), and the restorability class. Capture points are architectural and pre-declared, not discretionary — C1 pre-boundary (before an exchange window opens), C2 post-adjudication (after an operator ruling lands), C3 session close — so capture happens where the state exists, at formation; nothing is reconstructed afterward from transcripts. This is the AR-2 inversion made structural (§2.4): the capture boundary moves from the end of the pipeline, where a human curator's survivorship bias laundered itself as completeness, to a property of the pipeline itself. The manifest also types **restore** against **continuation** — a typing v1.6 lacked and needed. State transfer alone restores the substrate byte-exactly (restore class: what arrives is bitwise what was stored). Replaying forward from a capture point additionally requires the sampling seed and the environment inputs (continuation class). v1.6's implicit instruction — "read the repo and carry on" — conflated the two; the distinction inherits D1's lesson (recompute ≠ rewrite-detection): what verification can certify differs per class, so the manifest names the class per row instead of leaving it implicit in prose. The seed enters the unit here: a capture that claims continuation-class restorability pins the seed alongside the state; a capture that claims only restore-class does not, and says so.

### 3.3 State transfer, not summary

The movement operator for memory is **transfer**: bitwise-identical restore at the receiving end, certified by digest match. Summaries are navigation indices into the substrate — pointers, never payload (AR-6). The serialization chasm existed because text was asked to do what tensors do natively. On a text medium, byte-exactness had to be fought for at every relay: a single in-band markdown relay mutated 80 space bytes into non-breaking spaces, shifting a raw paste from 11,772 B to ~11,833 B against an on-disk pin (R2-56) — byte-level drift is the default behavior of browser-mediated text, not an anomaly. On a tensor medium, the canonical byte encoding is the native serialization and digest match is the native integrity check. The v1.7 inversion does not add discipline; it removes a tax. The transition instance is the live counterweight stack — WITNESS-CORE, the first-message packet, per-session delta files, and the operator voice notes (port package §3) — which is this same operator running on a text-only medium pending the tensor medium (§4). Delta files carry the state the summary provably drops (facts survive; texture, trust history, tone, and open-thread pointers drop), and the threshold rule (the archive grows only what the core or a delta references; core-hit rate < 30% over N sessions = past diminishing returns) keeps the archive itself from decaying into an unpriced summary of everything. The honest limit of the transition instance is named rather than absorbed: on a text medium the fidelity class is *hash-pinned at rest*, not *byte-exact in motion* — the motion tax is reduced at internal relays but remains possible at every boundary where text moves (R2-56-class events). The stack is the proof the discipline is implementable before the medium lands; it is not a claim that the medium has landed.

### 3.4 Text demoted to adjudication interface

Text survives in exactly two roles, and storage is not one of them. (i) The **adjudication channel**: envelopes, rulings, restatements — the human-verifiable exchange in which the human is the verifier of record. (ii) **Navigation indices**: summaries as pointers into the substrate, so that a successor can find what to read without being told (§7 of the record's own protocol is this principle in production). Every remaining serialization event is one whose loss is accounted — the §2.5 promise, made structural here as a named ledger. Each boundary where text touches the substrate is a declared conversion with a declared fidelity class: capture-point manifest → prose receipt (digest print, dual-channel record); adjudication prose → archive (the session close sequence: archive, manifest pin, single atomic commit; PROTOCOL §5.1). A conversion that does not appear on this ledger is a defect on sight. The window incident is the motivating instance: a rehydrated instance satisfied its ingest duty from the memory of a summary rather than a read, and drifted into freeform emission (Task-44 class; 2026-10-23) — the model-side endpoint of unaccounted serialization. The emission-shape rules already running on the text medium (CEE/1.0 + RT/1.0 envelopes, the bootstrap mandate, AFT) are the adjudication channel's integrity discipline; §3 does not replace them, it re-scopes them: they govern the interface, not the substrate.

### 3.5 The working tensor: why the delta-rule state

The substrate candidate needs four properties, each load-bearing for the archival atom of §3.2. **Finite**: the state at any capture point is a complete, enumerable object — nothing outside it is required for restore, so the manifest row certifies the whole of what is held. **Explicit**: a first-class object in the forward pass — addressable, hashable, checkpointable — not an emergent byproduct that must be excavated. **Fixed-size**: O(d²) per layer, independent of interaction length — the cost of a capture does not grow with how long the collaboration has run, and the manifest stays bounded no matter how much history it pins. **Rule-evolved**: the learned update rule has already decided, at the moment of capture, what to keep and what to overwrite — the state *is* the stream's memory, so capture mid-stream is well-defined rather than an arbitrary slice. Against the alternatives: the KV cache is explicit and checkpointable but unbounded — it grows with context, so an archival atom built on it inherits the interaction's length and the manifest has no natural size floor; the parametric layer is frozen at inference — no runtime write path exists, and the training-side reach into it (delta snapshots as memory deltas) is §4's subject, a training-time mechanism, never a claim of runtime write. The delta-rule lineage the collaboration's own record already surveys carries this state: DeltaNet → GDN → KDA → GDN-2 → MesaNet (record: PROJECT_STATE Task 19; charter §2). v1.6 named the missing tier — the across-context layer — and verified its absence across the lineage's published surfaces; §3 lands the claim where v1.6 left it: the fixed-size recurrent state is the natural substrate for the missing tier, because its four properties are exactly the properties the archival atom needs (§3.2) and could not obtain from text (§2.5). Confidence, stated as such: the property profile is verifiable from the published architectures; the claim that this profile suffices for collaboration memory is this program's thesis, not a premise — §7's evaluation battery is where it is tested, never asserted here.

### 3.6 The re-typed stack, one table

| Layer | v1.6-line (text-first) | v1.7 (tensor-first) |
|---|---|---|
| Parametric | frozen at inference; no runtime write path; unreachable by the collaboration | still frozen at inference (a vendor property, named as such); training-side delta snapshots become memory deltas (§4) — a bounded write path at training time, never a runtime claim |
| Activational | ephemeral by platform design; dies with the window; platform-owned | the working tensor: fixed-size recurrent state, checkpointed at pre-declared capture points (§3.2) — the substrate candidate |
| Archival | prose documents; hash-pinned at rest; manifest over strings (sessions/MANIFEST) | state checkpoints; manifest over states (§3.2); text demoted to adjudication interface + navigation indices (§3.4) |

The table is the inversion in one view; every right-hand cell exists because the corresponding left-hand cell's costs were measured, not suspected (§2). The live stack's position is stated honestly: the GWM record today is the transition instance — row three's left cell under the strictest discipline available on a text medium (append-only history, hash-pinned at rest, manifests, delta files, liveness probes, the §10 delivery medium). It is not yet tensor-first, and this section does not claim it is; §3 is the architecture the negative results force, §4 is the integration path by which the medium lands, and the transition instance is the proof the discipline carries until then.

### 3.7 Non-claims and scope

Fidelity, not veracity: byte-exact transfer certifies that what arrives is what was stored — it certifies nothing about whether what was stored is true. A poisoned tensor pins as permanently as a true one (§2.10). The veracity floor is unchanged by this architecture: detectability at n=1, never prevention (R2-35); the probe basis is partial and probabilistic, not preventive (session-012 design response); provider-level monism is named residue, not a solved problem. Cross-hardware bitwise replay remains disclaimed (carried from §2.10). The evidence base is an n=1 field program; no population-level generalization is claimed, and comparisons across model configurations are logged with the same neutrality whichever way they resolve — the protocol's model-independence datapoint (executed correctly across two model classes from cold start; record: session-013 close, item 4) is one datapoint, not a population claim. §3.5's property profile is asserted of the published architectures only; sufficiency for collaboration memory is the thesis under test in §7, not a premise of the architecture. Unfalsifiable residue has been cut from this section on sight per the evidence standard.
